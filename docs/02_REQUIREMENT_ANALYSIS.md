## ⚙️ 1. 기능 요구사항 (Functional Requirements)

### 🌍 F1. 글로벌 교과 과정 (Scale Expansion)
- 8개국(한국, 미국, 일본, 영국, 프랑스, 독일, 이탈리아, 중국)의 표준 교육과정을 지식 베이스로 사용합니다.
- 총 **288개 모듈** (8개국 × 3개 학교급 × 3개 과목 × 4개 단원) 규격의 학습 경로를 제공해야 합니다.

### 👤 F2. 사용자 프로필 및 온보딩
- 사용자는 본인의 닉네임, 학교급(`Elementary`, `Middle`, `High`), 그리고 **관심사 표상(직접 입력)**을 설정할 수 있어야 합니다.
- **Dynamic Context**: 학교급 선택에 따라 UI 테마, 타이포그래피, AI 어조(Tone & Manner)가 즉각적으로 동기화되어야 합니다.
- Firebase Auth를 통한 **Google Auth 소셜 로그인**을 지원해야 합니다.

### 🧠 F3. 인터랙티브 스토리 엔진
- AI는 사용자의 수준과 관심사를 실시간으로 프롬프팅하여 맞춤형 텍스트를 반환해야 합니다.
- 스토리 전개 중 **학습자의 선택(Choice)에 따른 분기(Branch)**가 발생해야 하며, 그 결과 인과관계(Consequences)를 즉각 피드백해야 합니다.
- 현재 장면의 맥락(Context)과 일치하는 16:9 비율의 **배경 이미지를 매 장면마다 실시간 렌더링**해야 합니다.

### 🏆 F4. 게이미피케이션 및 성취도
- 학습 진도와 퀴즈 득점률을 기반으로 5대 등급(`Bronze` ~ `Diamond`) 티어 시스템을 부여해야 합니다.
- 과목 혹은 단원 클리어 시 특정 **배지(Badge)**를 획득하고, 프로필의 대표 칭호로 설정할 수 있어야 합니다.
- 유저 타임라인(스토리 로그)을 저장하여 '나의 발자취' 형태로 다시 감상할 수 있어야 합니다.

---

## 🛡 2. 비기능 요구사항 (Non-functional Requirements)

### 🎨 N1. 사용자 경험 (UX/UI)
- 학습 도구가 아닌 **'게임'**의 느낌을 극대화하기 위해 프리미엄 UI 패키지(`Magic UI`, `Framer Motion`)를 적극 활용합니다.
- 비주얼 노벨에 걸맞게 시각 정보 영역(좌측)과 상호작용 및 동작 영역(우측)을 분할하는 모던 레이아웃을 채택합니다.

### 🚀 N2. 성능 및 확장성 (Performance)
- AI 이미지 생성 시간을 고려하여 **스켈레톤 UI(Shimmer 효과)**를 제공, 체감형 시각적 지연을 최소화합니다.
- 새로운 교과 데이터(사회, 과학, 철학 등) 확장 시, 코드 비즈니스 로직 수정 없이 데이터 JSON 주입만으로 확장이 가능한 **추상화 구조**여야 합니다.

### 🔐 N3. 데이터 정합성 / 보안 (Security)
- Firestore **Security Rules**를 적용, 작성자 본인의 고유 UID를 통해서만 해당 데이터 세트에 C/R/U/D가 가능해야 합니다.
- AI의 응답 데이터 포맷은 지정된 **JSON Schema 구조**를 엄격히 강제하여, 프론트엔드 파싱 크래시(Crash)를 예방해야 합니다.

## 🔬 3. 하이브리드 검증 (Hybrid Verification Requirements)

| 검증 단계 | 방법론 | 상세 내용 |
| :--- | :--- | :--- |
| **Hallucination Check** | 키워드 매칭 | AI가 반환한 텍스트 덩어리에 핵심 교육 키워드(예: '삼권분립')의 누락 여부를 스크립트 단에서 체크합니다. |
| **Persona Testing** | 시나리오 기반 | '초등학생 + 역사(공룡) 관심 + 다국어' 등 극단적 페르소나 조합 생성 시의 UI 무결성 및 프롬프트 탈옥 여부를 확인합니다. |
